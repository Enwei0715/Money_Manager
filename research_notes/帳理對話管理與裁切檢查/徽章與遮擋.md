# 徽章與遮擋（徽章、計數、浮動按鈕、疊加元素被裁切或遮住）

來源：只讀程式碼與模擬器截圖（shots3/）。路徑皆相對於 `app/src/main/java/com/enwei/moneymanager/ui/`。Compose BOM `2024.12.01`（material3 1.3.x），見 `gradle/libs.versions.toml:11`。本機沒有 material3 原始碼，所以 IconButton/BadgedBox 的內部尺寸是依該版本的已知實作推論，下面都標成「推論」。

## 一、使用者回報的「新聞紅色數字被擋住（右上方）」在哪、為什麼被裁

### Takeaway
最可能的位置是「投資 → 新聞」工具列「篩選」圖示上的紅色 M3 `Badge`（`screens/AdvisorScreen.kt:1177-1181`）。它和同檔另外兩個紅色計數（`:253-257` 報告歷史、`:781-784` 過去的對話）都是 `IconButton { BadgedBox { Icon } }` 的寫法。徽章會畫到 24dp 圖示的右上角外面，但 M3 IconButton 會把內容裁成 40dp 圓形，所以徽章的右上角被切掉。這幾處都沒有包 `ChromeScale`，大字級時徽章跟著放大（10sp × 最多 2 倍），被切得更多。

### Cited Findings
- 新聞篩選徽章：`androidx.compose.material3.IconButton(onClick = { filterOpen = true }) { BadgedBox(badge = { if (filterCount > 0) Badge { Text("$filterCount", fontSize = AppText.badge) } }) { Icon(Tune …) } }`。來源：`screens/AdvisorScreen.kt:1177-1181`。`filterCount` 的計算在 `:1155`。
- 同樣寫法的紅色計數還有兩處：
  - 今日報告的「報告歷史」數量：`screens/AdvisorScreen.kt:253-257`。數量是 `history.size+1`，常會到兩位數。
  - 問 AI 的「過去的對話」數量：`screens/AdvisorScreen.kt:781-784`（`chatThreads.size`），也會到兩位數。
- `Badge` 不指定 `containerColor` 時是 `colorScheme.error`，也就是紅色。上面三處都沒有指定。來源：同上三處，都只寫 `Badge { Text(...) }`。
- 字級：`AppText.badge = 10sp`（`Theme.kt:276`）。全域字級是 `fontScale.coerceIn(0.85f, 2f) * textScale`（`Theme.kt:218`）；`ChromeScale` 會把字級壓到 1.15 倍以下（`Theme.kt:285-288`）。
  - 交易頁的待確認徽章包在 `ChromeScale { TopAppBar … }` 裡（`screens/TransactionsTab.kt:268, 288-291`）。
  - 投資頁的三個徽章都在 `CollapsingTop` 的 header 或內容裡，沒有包 ChromeScale（`AdvisorScreen.kt:1157`、`:239`、`:777`）。
- 截圖對照：
  - `16_txns_after_notifications.png` 和 `26_bigfont_txns.png` 裡，交易頁鈴鐺上的「1」是完整的。單一位數加上 ChromeScale，徽章剛好落在圓形裁切範圍內。
  - `09_assistant.png` 的新聞工具列當時沒有篩選（filterCount=0），所以看不到徽章，截圖沒拍到被裁的樣子。
- 外層容器：`CollapsingTop` 用了 `clipToBounds()`（`components/CollapsingTop.kt:43`）。新聞頁是兩層 CollapsingTop：外層 `AdvisorScreen.kt:153`，內層 `:1157`。工具列是內層 header 的第一列，上方只有 `top = 6.dp` 的 padding（`:1160`）。

### Inferences
- 推論（material3 1.3 的實作）：
  - IconButton 的寫法是 `minimumInteractiveComponentSize().size(40.dp).clip(CircleShape)`。24dp 圖示位在 40dp 圓的 8–32dp 之間。
  - BadgedBox 把帶文字的徽章放在圖示右上角往外約 4–6dp。單一位數的徽章寬約 16dp，在 1.0–1.15 倍字級下勉強落在圓內，交易頁鈴鐺就是這種情況。
- 徽章被切的三種情況：
  - 兩位數，例如報告歷史「12」或對話數「15」。徽章寬約 22dp 以上，右緣超出 40dp 圓。
  - 字級大於 1.15 倍。投資頁沒有包 ChromeScale，徽章會長到約 20sp，向右上撐出圓外。
  - 圓形裁切本身。右上角正好是圓切得最多的位置，所以使用者看到的是「右上方被擋住」。
- 外層 CollapsingTop 的 `clipToBounds` 只在大字級時才可能再切到徽章頂端：工具列距離 CollapsingTop 頂端只有 6dp，徽章往上超出圖示約 8–14dp。這不是主因。
- 重現步驟：投資 → 新聞 → 篩選，選任一條件，例如「利多」。然後把系統字級調到最大，或改用報告歷史兩位數的情況。

### Gaps
- 沒有「新聞篩選啟用時」或「報告歷史兩位數」的截圖，無法用畫面直接確認哪一顆是使用者指的那顆。不過三顆的寫法和風險一樣，修法也相同。
- 沒有 material3 1.3.x 原始碼可以核對 BadgedBox 的確切位移（dp）。

## 二、其他同類風險清單（file:line、被切或被擋的內容、重現、修法）

### Takeaway
紅色計數徽章一共 4 顆，都是「IconButton 包 BadgedBox」，同一類問題。另外有 3 類遮擋：
- 浮動按鈕（FAB）蓋住列表右側的金額，大字級時整個金額被遮。
- 會裁切的容器（clipToBounds）把畫布標籤或日曆格內容切掉。
- 固定高度的格子在大字級下溢出。

底部的 UndoBar 和 AiStatusBar 放在 Scaffold 的 bottomBar 裡，會佔用版面高度，不會疊在內容上，沒有問題。

### Cited Findings

**A. 紅色計數徽章（同一類）**

| # | 位置 | 被切的內容 | 重現 | 嚴重度 |
|---|---|---|---|---|
| A1 | `screens/AdvisorScreen.kt:1177-1181` | 新聞「篩選」數量 | 開篩選，大字級 | 高（即使用者回報） |
| A2 | `screens/AdvisorScreen.kt:253-257` | 報告歷史數量，常是兩位數 | 累積 10 份報告以上 | 高 |
| A3 | `screens/AdvisorScreen.kt:781-784` | 過去的對話數量 | 10 段對話以上 | 高 |
| A4 | `screens/TransactionsTab.kt:288-291` | 待確認數量（`pending + pendingTrades`） | 待確認 10 筆以上。字級已被 ChromeScale 壓住，目前一位數時截圖正常 | 中 |
| A5 | `screens/TxnEditor.kt:588` | 無文字的小點徽章（primary 色） | 小點大約 6dp，風險低 | 低 |

**B. 浮動按鈕遮住內容**
- `screens/TransactionsTab.kt:298-305`：64dp FAB 放在右下角，正好蓋住列表右側對齊的金額。
  - 列表最後有 `Spacer(96.dp)`（`:586`），所以只有最後一筆捲得出來；捲動途中的列一定被蓋住。
  - 截圖 `16_txns_after_notifications.png`：「10 週二」那列的日合計只剩最後一位「0」。
  - 截圖 `26_bigfont_txns.png`：「台科大第一餐廳 −$ 120.00」只看得到「−$」。
  - 修法：往下捲時把 FAB 收起，跟 `Chrome.bottomHidden` 連動，例如 `AnimatedVisibility(!Chrome.bottomHidden)`；或改成可縮小的 ExtendedFAB。
- `screens/RecurringScreens.kt:78`，列表尾端留 `Spacer(88.dp)`（`:121`）：同樣的模式，列右側的金額或日期會被蓋住。
- `screens/InvestScreens.kt:391-392`，尾端留 `Spacer(88.dp)`（`:469`）：交易紀錄右側的金額會被蓋住。
- `screens/AdvisorScreen.kt:883-887`：「到最新」的 SmallFAB 放在聊天列表右下角，會蓋住最後幾則訊息的右下角。只在往上捲時出現，影響小。

**C. 裁切容器切到標籤或內容**
- `screens/StockDetailScreen.kt:1290`：190dp 的 Canvas 加了 `clipToBounds()`。
  - `tag()`（`:1295-1301`）以 `yMid` 為中心畫一個 22k 高的標籤底框，只限制了 x（`coerceAtLeast(0f)`），沒有限制 y。
  - 當價位線接近圖的頂端或底端時，`y()` 被限制在 2..h-2，標籤會有一半被切掉。
  - 修法：`yMid.coerceIn(12f*k, size.height-10f*k)`。
- `screens/TransactionsTab.kt:898`：月曆格在 fit 模式下用 `clipToBounds()`，格內的筆數或金額超出格高時被直接切掉，不會出現「+N」提示。大字級時更明顯。
- `screens/TransactionsTab.kt:1205`：年曆每格固定 110dp 高（`:1200`）並 `clipToBounds()`，大字級時下面幾行收支被切掉。
- `components/MiniCharts.kt:299`（160dp Canvas）、`screens/SpendMapScreen.kt:217/677/688`：都用了 `clipToBounds`，主要是畫線和地圖，預期中的裁切，沒看到標籤被切。
- `components/CollapsingTop.kt:43`：這個 `clipToBounds` 是共用的。任何放在 header 第一列、往上超出的疊加元素（徽章、提示氣泡）都會被它切掉。

**D. 其他疊加元素，檢查後沒有問題**
- `screens/ToolGrid.kt:210`：編輯模式右上角的移除鈕用 `align(TopEnd).padding(6.dp)`，放在格子內側（註解寫明「不壓到外框」）。這是正確的寫法，可以當範本。
- `MainActivity.kt:340-361`：UndoBar 和 AiStatusBar 放在外層 Scaffold 的 `bottomBar` 裡，內容會拿到 inner padding，不會被蓋住。
- `screens/StatsTab.kt:189`、`screens/TransactionsTab.kt:272`：`offset(x = -12.dp)` 是把標題往左對齊，在 TopAppBar 標題槽內，沒有看到被切。
- 底部分頁（`MainActivity.kt:263-289`）目前沒有徽章。

### Inferences
- 會被切的寫法有三種共同模式：
  - 疊加元素刻意畫在母元件邊界外，例如 BadgedBox 往右上偏移。
  - 母元件會裁切，例如 IconButton 的圓形、`clipToBounds`、Surface 或 Card 的圓角。
  - 尺寸跟著字級長大，但沒有預留空間。
- 浮動按鈕的問題則是「疊在可捲動列表右側重要資訊上，只靠列表尾端的 Spacer 處理」。

### Gaps
- 沒有逐一截圖驗證 RecurringScreens 和 InvestScreens 的 FAB 遮擋，以及股票 Canvas 標籤在邊緣被切的情況，這幾項是依程式碼推論。
- 沒有檢查所有 Dialog 和 BottomSheet 內的疊加元素。

## 三、一次防止整類問題的規則與共用元件

### Takeaway
新增一個共用的 `CountBadge` 和 `BadgedIcon`。徽章一律畫在 48dp 觸控區的內側右上角，不用 BadgedBox 的外推偏移，也不放進會裁切的 IconButton 內容裡。所有頁面的 FAB 改用統一的捲動收起，加上統一的底部留白常數。

### Cited Findings
- 現有範本：`screens/ToolGrid.kt:210` 用 `align(TopEnd).padding(6.dp)` 把元素放在內側。
- 字級上限的工具：`ChromeScale`，`Theme.kt:285-288`。
- 捲動狀態：`Chrome.bottomHidden`，`components/CollapsingTop.kt` 的 `Chrome` 物件。

### Inferences
- 建議元件，放在 `components/Badges.kt`：
  ```kotlin
  @Composable
  fun BadgedIconButton(icon: ImageVector, desc: String, count: Int, onClick: () -> Unit, tint: Color = LocalContentColor.current) {
      Box(Modifier.size(48.dp).clickable(role = Role.Button, onClick = onClick), contentAlignment = Alignment.Center) {
          Icon(icon, desc, tint = tint)
          if (count > 0) CountBadge(count, Modifier.align(Alignment.TopEnd).padding(top = 4.dp, end = 2.dp))
      }
  }
  @Composable
  fun CountBadge(count: Int, modifier: Modifier = Modifier) = ChromeScale {
      Surface(color = MaterialTheme.colorScheme.error, shape = RoundedCornerShape(50), modifier = modifier) {
          Text(if (count > 99) "99+" else "$count", fontSize = AppText.badge, color = MaterialTheme.colorScheme.onError,
               maxLines = 1, modifier = Modifier.defaultMinSize(minWidth = 16.dp).padding(horizontal = 4.dp), textAlign = TextAlign.Center)
      }
  }
  ```
  - 用這個元件取代 A1–A4（`AdvisorScreen.kt:254, 782, 1178`、`TransactionsTab.kt:290`）。
  - 規則：
    1. 不使用 `IconButton { BadgedBox }`。
    2. 徽章不使用負的 offset。
    3. 一律包 ChromeScale 並封頂「99+」。
- FAB 規則：
  - 新增 `ScrollAwareFab`，用 `AnimatedVisibility(!Chrome.bottomHidden)` 包住 FAB，套到 `TransactionsTab.kt:301`、`RecurringScreens.kt:78`、`InvestScreens.kt:392`。
  - 列表尾端的留白統一成 `Dimens.fabClearance = 96.dp`，取代 88dp 和 96dp 混用。
- 裁切容器規則：
  - 在 `clipToBounds` 或固定高度的容器裡，畫布標籤一律把 x 和 y 都限制在容器內。可以寫一個 `drawTagInBounds()` helper，套到 `StockDetailScreen.kt:1295`。
  - 固定高的日曆格超出時顯示「+N」，不要直接切掉（`TransactionsTab.kt:898, 1205`）。
- 驗收：加一張「篩選啟用＋最大字級」和一張「報告歷史 12 份」的截圖腳本，放進 shots 流程。

### Gaps
- 元件尚未實作與編譯驗證，這次是唯讀研究。
