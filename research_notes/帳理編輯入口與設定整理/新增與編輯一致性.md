# 新增與編輯一致性、隱藏入口盤點（帳理 Ledgerly）

> 範圍：只讀原始碼，未改專案檔。路徑前綴 `ui/screens/` = `app/src/main/java/com/enwei/moneymanager/ui/screens/`；`data/` 同理。行號以 2026-11-13 工作目錄為準。

## 1. TxnEditor.kt 的 `original == null / != null` 閘門逐一盤點

### Takeaway
記帳頁共有 10 處「只在新增」或「只在編輯」的閘門。真正造成功能缺口的是「手續費」（編輯時入口與欄位都不顯示）、「誰還的（還款）」（編輯收入時不能改成還款），以及「分帳」（編輯時看得到但不載入舊的分帳，再加一次會重複拆帳）。根本原因是手續費、代墊轉帳都是另外存的獨立交易，和主交易之間沒有任何關聯欄位。

- 手續費存法：`saveFee()` 另存一筆 EXPENSE，帳戶、日期（同一個毫秒）與主交易相同；商家設為「轉帳手續費」或「<商家> 手續費」，分類優先選名稱含「手續費」的分類（TxnEditor.kt:443-455）。
- TxnEntity 沒有 parent 或 link 欄位，只有 `externalKey`（唯一索引）與 `recurringId`（data/Entities.kt:76-104）。
- `deleteTxn` 只刪除單一筆，不會連帶刪除手續費或代墊轉帳（data/Repository.kt:273-282）。
- 分帳的存法：自己的部分以原 id 存成支出，note 附加「共 X，代墊 A 100」；每個人的部分**新增**一筆轉帳到他的往來帳戶，商家為「代墊：<商家>」，同樣沒有關聯欄位（data/Repository.kt:639-681）。
- `externalKey` 目前的前綴：`R:`、`AP:`、`REBATE:`、`AX:`、`N:`、`DIV:`、`MM:` 等，沒有任何手續費用途（data/Repository.kt:1254、1877、1902、1950；data/MmbakIO.kt:209、336）。
- 「往來」模式 (debtMode) 的入口 `debtOpen` 從未被設為 true；DebtPicker 與 DebtInline 實際上是死碼（TxnEditor.kt:175、566、615）。往來的功能已整合進分帳與「誰還的」（TxnEditor.kt:601 的註解）。

### Inferences
- **編輯時的手續費建議做法**（不需要 DB migration）：
  1. 關聯：新增手續費時設定 `externalKey = "FEE:<主交易id>"`。唯一索引保證一筆主交易最多一筆手續費，查詢可用既有的 `byExternalKey`（data/Daos.kt:95）。新增路徑要先拿到主交易 id：一般路徑已有 `newId`（TxnEditor.kt:510）；「別人先付」與分帳路徑目前丟掉了 saveTxn／saveWithSplits 的回傳值，要接起來。
  2. 舊資料：沒有 key 的舊手續費用啟發式比對，條件為 `type == EXPENSE`、`date == 主交易.date`（saveFee 用同一個毫秒，比對很準）、`accountId` 相同、`merchant == "轉帳手續費"` 或以「手續費」結尾、`source == MANUAL`。找到後順手補上 `FEE:` key。
  3. 載入：編輯時找到手續費 → `feeExpr` 帶入金額、`showFee = true`、連結顯示「手續費 ✓」。
  4. 儲存：有 → 更新金額、帳戶、日期、幣別；原本有、現在清空 → 刪除；原本沒有 → 新增並設定 key。
  5. 刪除主交易時一併刪除手續費，Undo 要同時還原兩筆（TxnEditor.kt:875-881 目前只還原 `gone`）。
  6. 另一個選擇是新增 `linkedTxnId` 欄位（AppDatabase version 6 → 7，data/AppDatabase.kt:16）。這樣可以同時解決分帳轉帳的關聯，但工程量較大。
  7. 待確認的通知交易（「確認入帳」按鈕，TxnEditor.kt:871）走的是編輯流程，所以目前**連通知記下的轉帳都無法補手續費**。這正是最常需要加手續費的情境（銀行轉帳通知），修正價值高。
- **分帳編輯風險（F）**：編輯一筆已分帳的支出時，金額欄顯示的是「自己的部分」，分帳列是空的。如果再勾選分帳，會用這個較小的金額再拆一次，並新增轉帳，造成重複代墊。建議二選一：(a) 偵測 note 的「共 X，代墊」或同日、同帳戶、商家為「代墊：…」的轉帳，在編輯頁顯示唯讀提示「此筆已分帳：A 100（點此查看）」，並停用再分帳；(b) 比照手續費，改用 `SPLIT:<主id>:<序號>` 關聯後重建分帳。
- 「週期/分期」(TxnEditor.kt:655-664) 應改成帶參數，例如 `recurring/0?amount=&type=&account=&cat=&name=`。編輯時文字可改成「設為週期」，讓使用者從既有交易建立週期規則。

### Gaps
- 沒有實機測試編輯分帳交易時的實際畫面，F 的重複拆帳風險是由程式碼推論。
- `.mmbak` 匯出（data/MmbakIO.kt:336）只保留 `MM:` 開頭的 key，其他 key 會換成隨機 UID。改用 `FEE:` key 時，經 .mmbak 來回匯出匯入是否會遺失關聯，還沒有逐行驗證匯入端。

## 2. 其他編輯器的新增與編輯落差

### Takeaway
股票交易、帳戶、週期、分類、預算這幾個編輯器的新增與編輯欄位大致一致，沒有像手續費這樣的功能缺口。主要問題是**刪除行為不一致**（週期交易按了直接刪除、沒有確認也不能復原）、「週期/分期」名稱與實際功能不符，以及股票交易沒有「複製」。

### Cited Findings
- **TradeEditor**（ui/screens/InvestScreens.kt）
  - 新增時會從待補成交通知帶入資料，並用報價帶入成交價（InvestScreens.kt:551-588）。這是預填，不是欄位差異，合理。
  - 「保本紀律」提示只在新增賣出時顯示（InvestScreens.kt:679-680），存檔後的 `adjustGuardAfterSell` 也只在新增時執行（InvestScreens.kt:743）。編輯舊的賣出不重算保本，避免重複調整，合理。
  - 手續費、交易稅欄位在新增與編輯時都有（InvestScreens.kt:704-705）。編輯時輸入沒變就保留原本的手續費（InvestScreens.kt:537、598）。
  - 刪除入口重複：右上垃圾桶與底部「刪除這筆交易」都只在編輯時出現，兩者都會確認（InvestScreens.kt:618、754-758、761-787）。
  - 沒有「複製／再記一筆」（TxnEditor 編輯時有「複製」，TxnEditor.kt:882-893）。
- **AccountEditor**（ui/screens/AccountScreens.kt）：所有欄位在新增與編輯時都一樣，只有刪除（AccountScreens.kt:146）與說明「修改目前餘額會調整期初餘額」（AccountScreens.kt:424）限編輯。群組（類型）在編輯時可以改（AccountScreens.kt:154-163）。
- **RecurringEditor**（ui/screens/RecurringScreens.kt）：欄位在新增與編輯時一致。
  - 刪除：右上圖示按下**立即刪除，不確認也不能復原**（RecurringScreens.kt:163-165），和交易（直接刪除＋Undo，TxnEditor.kt:875-881）、帳戶與股票（AlertDialog 確認）三種做法都不同。
  - 沒有「分期」欄位，分期要靠「設定結束日期」自己湊（說明見 RecurringScreens.kt:72）。TxnEditor 的「週期/分期」按鈕名稱因此會讓人誤會。
  - RecurringEntity 沒有 merchant 欄位（data/Entities.kt:108-129），所以產生的交易沒有商家；記帳頁有商家，兩邊不一致。
- **分類**（ui/screens/CategoryScreens.kt:229-282）：「隱藏」開關與「移為子分類／移至其他大分類」只在編輯時出現（CategoryScreens.kt:245、249）。新增大分類時不能直接指定為子分類，要到子分類頁新增（CategoryScreens.kt:181）。差異輕微。
- **預算**（ui/screens/ConfigScreens.kt:567-680）：新增與編輯共用同一個對話框，沒有落差。
- **往來／借貸**（ui/screens/DebtScreens.kt:126-162、LoanScreens.kt:57-59）：各人的「記錄代墊／他幫我付／收回款項或還款／借貸細節」**全部收在每列右側的 ⋮ 選單**（DebtScreens.kt:148-159）。
- **店家位置**（ui/screens/MerchantPlacesScreen.kt:280-322）：「Google 地圖連結、用目前位置、不是實體店、清除位置」收在灰色小字「其他方式」後面（MerchantPlacesScreen.kt:299-300）。

### Inferences
- 建議統一刪除模式：直接刪除＋Undo snackbar（交易頁已有的做法）。週期交易至少要補上 Undo。
- TradeEditor 可補「複製」，方便定期定額或同一檔股票分批買進。

### Gaps
- 沒有逐行檢查 StockFeeScreen、AccountGroupScreens 的編輯行為（這兩頁都是設定頁，不是新增／編輯成對的表單）。

## 3. 不顯眼或隱藏的入口

### Takeaway
最明顯的是記帳頁的兩個小字入口：「＋手續費」（13sp 純文字，位在金額右上角）和「週期/分期」（10sp 灰字，夾在日期列右側圖示下）。另外有三種長按操作完全沒有提示，以及帳戶頁把「新增帳戶」藏進 ⋮ 選單。

### Cited Findings
- 字級定義：caption 13sp、label 12sp、badge 10sp（ui/Theme.kt:268-277）。
- 「＋手續費」是 `AppText.caption` 純文字，點擊範圍只有內距 4dp（TxnEditor.kt:630-631），不到 48dp。唯一的說明是首次導覽裡的一句「右上角可加入手續費」（TxnEditor.kt:216）。
- 「週期/分期」是 `AppText.badge` 10sp 灰字加 20dp 圖示（TxnEditor.kt:655-664）。
- 交易列表長按進入多選（TransactionsTab.kt:718-720、767-769），畫面上沒有任何「長按可多選」的提示（TransactionsTab.kt:178 只有程式註解）。
- 日曆長按某天直接記帳（TransactionsTab.kt:903）。有 12sp 小字提示「長按日期記一筆」（TransactionsTab.kt:371），日曆分頁也沒有 FAB（TransactionsTab.kt:300-305）。
- AI 對話泡泡長按才有「複製／編輯後重問／刪除」（AdvisorScreen.kt:1027、1041-1046），沒有提示。
- 工具格長按進入編輯：有右上「編輯」按鈕，也有導覽說明（MoreScreens.kt:132、160；components/Coach.kt:80）。這個做法尚可。
- 帳戶頁「新增帳戶」只在 ⋮ 選單裡（AccountsTab.kt:219-221）；股票分頁則有 ＋ 圖示（AccountsTab.kt:214）。兩個分頁不一致。
- 往來每人的操作全部只在 ⋮ 選單（DebtScreens.kt:148-159）。

### Inferences
建議全頁統一的可見模式：
1. **表單附加項**（手續費、分帳、週期）：統一做成表單列底部的「＋ 加入手續費」整列按鈕（≥48dp、body 字級、左側圖示），加入後變成一般 FormRow，可以移除。新增與編輯一律顯示。
2. **長按操作**：至少提供一個可見的替代入口。交易列表在標題列放「選取」按鈕，或首次進入時用 Coach 說明；AI 泡泡在下方放小型「⋯」按鈕。
3. **主要新增動作**不放進 ⋮ 選單：帳戶頁補 ＋ 圖示或 FAB；往來列的「收回／還款」可做成列內的直接按鈕。
4. 「其他方式」灰字改成有箭頭的 TextButton。

### Gaps
- 沒有實機截圖確認實際大小與觸控範圍。觸控尺寸問題在任務 #49（P1 觸控範圍 48dp）也有涵蓋，可以合併處理。
