# 圓餅圖標籤重疊與底部分頁記憶規則（讀原始碼）

路徑皆相對於 `app/src/main/java/com/enwei/moneymanager/`。Navigation 版本 2.8.5（`gradle/libs.versions.toml:10`）。

## A. 統計圓餅以外，還有哪些圓餅／圓環圖？標籤會不會重疊？

### Takeaway
整個 UI 只有三個圓形圖：統計 `PieChart`（唯一有外圍標籤）、搜尋篩選的 `Donut`（只有中間一個百分比）、桌面小工具的甜甜圈點陣圖（沒有標籤）。其他「比例」都是橫條＋圖例，不會有扇形標籤互相重疊的問題。所以使用者說「其他畫面還會疊」，比較可能是指：同一個 `PieChart` 在窄螢幕、大字級或英文介面下出問題，而不是另一個圓餅。

### Cited Findings
- 全 UI 只有這些地方呼叫 `drawArc`：`ui/screens/StatsTab.kt:351,359`（PieChart）、`ui/screens/FilterScreen.kt:323-324`（Donut）、`widget/SummaryWidget.kt:127`（小工具）。程式裡沒有其他 Pie／Donut／sweep 繪圖 — `grep drawArc|PieChart|Donut|sweepAngle`
- `PieChart(` 只有一個呼叫點：`ui/screens/StatsTab.kt:248`。CategoryStatScreen（`StatsTab.kt:456` 起）是長條圖（`StatsTab.kt:481` 的 Canvas 22×100dp），沒有圓餅。
- **Donut**（`FilterScreen.kt:311-331`）：圓環中間只有一個 `Text("xx%")`，字級 `AppText.section`＝15sp（`Theme.kt:271`），下面兩行金額 `maxLines = 1`、沒有設定 `overflow`。唯一的使用處是搜尋篩選列 `TxnScreens.kt:222-223`，圓環 `ring = 58.dp`、粗 9dp，和「合計」欄三欄等寬並排（`weight(1f)`）。
  - 會出問題的地方：內孔直徑約 58−18＝40dp，「100%」在 15sp 半粗體大約 34–36dp；P0 拿掉字級上限之後，系統字級 1.3 倍時約 45dp，會壓到圓環上（推論，依字寬估算）。金額像「1,234,567」在三分之一螢幕寬、大字級下會被硬切（沒有 Ellipsis）。
  - 最小修正：中間的百分比改用現有的 `components/FitText.kt`，或把字級設成 `(ring - 2*9.dp) * 0.32`、`maxLines=1, softWrap=false`；兩行金額加上 `overflow = TextOverflow.Ellipsis`，或改用 FitText 共用字級。
- **桌面小工具**（`widget/SummaryWidget.kt:112-135`）：240px 點陣圖，圖上沒有字；圖例只放前三名、排成一行（`SummaryWidget.kt:76-83`），由 RemoteViews 的 TextView 排版。不會重疊，最多被截斷。
- **檢討的支出結構**（`ReviewScreen.kt:414-452`）：用橫條（`Row` 加 `weight` 的色塊，`:435-438`），圖例用 `FlowRow(maxItemsInEachRow = 2)`，名稱 `maxLines=1` 加 Ellipsis（`:440-446`）。不是圓餅，也不會重疊。
- **股票助理報告的資金分配**（`AdvisorScreen.kt:454-470`）：用橫條，圖例放在 `horizontalScroll` 的 Row 裡（`:461`），不會重疊。
- **紀律頁的資金配置**（`AdvisorScreen.kt:1612-1640`）：用橫條，圖例用 FlowRow（`:1633`），不會重疊。
- InvestScreens／MiniCharts 沒有圓餅：MiniCharts 只有 K 線、長條、比較線（`components/MiniCharts.kt:49,102,142,179`）。
- **統計 PieChart 修過之後還剩的風險**（`StatsTab.kt:331-452`）：
  1. 標籤寬度沒有限制：只在最後把 x 夾進畫面內（`StatsTab.kt:449` 的 `x.coerceIn(0f, size.width - w)`）。標籤太寬時會被往內推，壓到圓環或連接線上。在 360dp 寬的手機上，r＝0.27×W≈97dp（`:347`），標籤錨點在 1.28r（`:405,435`），右側只剩約 48dp。一行標籤（像「交通運輸 23.5%」或英文「Food & Dining 23.5%」）都比這寬。
  2. 中間的總額用 `AppText.title`＝18sp（`:342`, `Theme.kt:268`），內孔直徑是 1.2r≈116dp（`:363`）。像「NT$1,234,567」這種長金額，加上大字級，會壓到圓環。
  3. 改成一行、以及丟掉最小標籤，都只看高度（`:409,413`），不看寬度。

### Inferences
- 最小修正（StatsTab.kt）：
  - 量測標籤時給寬度限制：`measurer.measure(text, style, constraints = Constraints(maxWidth = side), maxLines = 2, overflow = TextOverflow.Ellipsis)`，其中 `side = size.width/2 - dx - 8f`。dx 要等 y 排好才知道，所以可以先用最保守的 `size.width/2 - r*1.28f - 8f`，最小保留約 56dp。
  - 中間的總額先量寬度；超過 `1.1f*r` 就改用較小字級（title→section→caption），或改用 FitText 的縮字邏輯。
- 要不要把 PieChart 做成共用元件？建議**搬到 `ui/components/Charts.kt` 當共用元件**，但**不要硬套到其他畫面**。原因：
  - Donut 是「單一比例的進度環」，本來就不需要分類標籤。
  - 檢討頁、助理頁、紀律頁的比例條＋圖例，在窄螢幕上反而比圓餅好讀、不會疊，應該保留。
  - 小工具是 RemoteViews 點陣圖，用不到 Compose。
  - 共用化的好處是之後如果有新的圓餅（例如帳戶資產分布）不會再複製一份。真正要修的是 PieChart 本身的寬度限制。
- 「不同畫面還會疊」最可能的原因：窄手機、大字級、英文介面，或期間切到「年」之後分類變多。以上都是 PieChart 本身的問題。

### Gaps
- 沒有實機或截圖驗證；字寬是依 sp 估算，沒有實際量測。
- 不確定使用者說的「不同畫面」是指不同頁面，還是不同螢幕尺寸，要請使用者提供截圖確認。

## B. 底部分頁的記憶規則：切到別的分頁再回來，會發生什麼事？

### Takeaway
`openTab` 對非起始頁的分頁用 `popUpTo(start){saveState=true}` 加 `restoreState=true`，所以統計、資產、投資、工具會**連子畫面整串一起記住**：工具→預算→切走→回工具，看到的還是預算。在子畫面裡再點一次同一個分頁，也會先存再原樣還原，看起來像點了沒反應。「交易」是起始頁，走 `popBackStack(start)`，所以永遠回到根頁。建議統一成「點底部分頁一定回到該分頁的根頁；頁內子分頁的選擇照舊記住」。

### Cited Findings
- `openTab` 的實作：`ui/MainActivity.kt:307-320`
  - 交易：`if (route == start.route) { if (!popBackStack(start.id, false)) navigate(route){launchSingleTop=true}; return }`（`:310-313`）
  - 其他分頁：`navigate(route) { popUpTo(start.id) { saveState = true }; launchSingleTop = true; restoreState = true }`（`:315-319`）
- 底部分頁列在所有「非編輯畫面」都會顯示，包含子畫面（`MainActivity.kt:338-339,345` 的 `showBar = !imeOpen && !editing`），亮起的是最後一個進過的分頁（`:336-337,349`）。所以使用者在「預算」畫面時，看到的是「工具」亮著。
- 工具格開啟子畫面走 `openRouteFrom` → `openRoute`。是分頁的就切分頁，其他一律 `navigate(r)` 疊在 more 上面（`MoreScreens.kt:169`；`MainActivity.kt:249-259`）。例如 `composable("budget")`（`:406`）。
- 分頁路由：txns／stats／accounts／assistant／more（`MainActivity.kt:267-274`）；對應的 composable 在 `:390-394` 和 `:508`。
- 各分頁實際行為（依程式碼推演，Navigation 2.8.5 的 saveState 機制）：
  - **交易**：交易→某筆明細→切到統計→回交易：`popBackStack(txns)` 會把上面的畫面全部清掉，永遠是根頁。被 `popUpTo(start){saveState}` 存起來的明細狀態不會再被還原，因為只有分頁路由會用 restoreState。日／月子分頁由 `rememberTab("txns.tab")`（`TransactionsTab.kt:191`）記住。
  - **統計**：統計→分類明細（CategoryStatScreen）→切到工具→回統計：還原整串，停在分類明細。檢視（明細／分析）、期間、收支種類由 `rememberTab("stats.view")`、`rememberChoice("stats.period")`、`rememberChoice("stats.kind")` 記住（`StatsTab.kt:142,145,161`）。
  - **資產**：資產→帳戶明細等子畫面：同樣會還原到子畫面。區塊由 `rememberTab("accounts.section")` 記住（`AccountsTab.kt:161`）。
  - **投資**（assistant）：子畫面同樣會被還原。子分頁由 `rememberTab("advisor.tab")` 記住（`AdvisorScreen.kt:141`）。
  - **工具**：工具→預算→切走→回工具：停在預算。使用者回報的就是這個。
  - **在子畫面再點同一個分頁**（例如在預算畫面點工具）：同一次 navigate 裡先 `popUpTo(start){saveState}` 把 [more, budget] 存起來，接著 `restoreState` 又把同一串還原，結果還是預算。這是 Navigation 已知的行為；這裡是推論，沒有讀到 2.8.5 的原始碼，見 Gaps。
- `rememberTab`／`rememberChoice` 存在 SharedPreferences，**永久**有效（重開 App 也會記住），沒有「當天」的期限（`components/TabMemory.kt:14-18,32-33,42-44`）。
- 深層連結／通知：
  - 冷啟動讀 `EXTRA_ROUTE`（`MainActivity.kt:118`）；熱啟動走 `onNewIntent`（`:221-226`），通知 Intent 帶 `SINGLE_TOP|CLEAR_TOP`（`notify/AppNotices.kt:83-90`）。兩者最後都是 `LaunchedEffect` → `nav.openRoute(r)`（`MainActivity.kt:160-172`）。
  - 通知用到的路由：`review`（`data/Budget.kt:86-87`、`work/SyncWorker.kt:221-223`；會轉成 `statsView=1` 加切到統計分頁，`MainActivity.kt:255`）、`advisor:0／1`（轉成切到投資分頁）、`accounts`、`settings`、`backup`、`pending`（`work/*.kt` 的 AppNotices.post）。
  - 小工具用到的路由：`txn/0?...`、`txns`、`stats`、`accounts`、`config`、`invest`（`widget/Widgets.kt:110-255`、`widget/SummaryWidget.kt:94-97`）。
  - 非分頁路由（settings、backup、pending、config、invest、txn/…）都是直接 `navigate(r)`，**疊在使用者當時停留的畫面上**（`MainActivity.kt:257`）。例如停在工具→預算時點「備份」通知，堆疊會變成 [txns, more, budget, backup]，按返回回到預算，底部亮著工具。這就是殘留的堆疊。
  - `invest` 是另一個非分頁路由（`MainActivity.kt:393`）：`AccountsTab(showBack=true, initialTab=1)` 疊在目前畫面上，而且會用 `remember { if (initialTab != 0) section = initialTab }` 把 `accounts.section` 的記憶改掉（`AccountsTab.kt:161-163`）。

### Inferences
- 建議規則：
  1. 點底部分頁一定顯示該分頁的根頁。
  2. 根頁本身的捲動位置和頁內 rememberSaveable 狀態（月份錨點等）可以保留。
  3. 頁內子分頁、檢視、期間的選擇照舊用 TabMemory 記住。要做到「只記當天」的話，在 TabMemory 多存一個日期。
  4. 通知和小工具一律先回到根頁再開目標畫面，不疊在舊堆疊上。
- 程式修改（MainActivity.kt:315-319，套用到所有非起始頁分頁，一致處理）：
  ```kotlin
  navigate(route) {
      popUpTo(start.id) { saveState = true }
      launchSingleTop = true
      restoreState = true          // 還原根頁的 rememberSaveable／捲動位置
  }
  popBackStack(route, inclusive = false)   // 再把還原回來的子畫面清掉，只留分頁根頁
  ```
  - 這樣也順便修好「在子畫面再點同一個分頁沒反應」。
  - 如果只想先改工具：`if (route == "more") popBackStack("more", false)`。
  - 更簡單的寫法是拿掉 saveState 和 restoreState（`popUpTo(start.id); launchSingleTop = true`），代價是統計的月份錨點、各分頁的捲動位置每次切回來都會重設（`StatsTab.kt:143,159` 的 rememberSaveable）。
- 「只記當天」的改法（可選，`components/TabMemory.kt:16-17`）：`set` 時另外寫入 `"$key.day" = LocalDate.now().toEpochDay()`；`get` 時如果日期不是今天就回傳 default。建議只套用在 stats.period、stats.kind 這類「期間」選擇；子分頁的選擇維持永久記憶。
- 深層連結的修法（MainActivity.kt:249-259 的 `openRoute`，或只在 :160-172 的 pendingRoute 處理器裡改）：非分頁路由先 `popBackStack(graph.findStartDestination().id, false)` 再 `navigate(r)`；更好的做法是先切到所屬分頁：settings／backup／pending／config → `openTab("more")` 後再 navigate；`txn/…` → 留在交易。
- `invest` 路由的修法：改成和 advisor 一樣的作法：`TabRequest.accountsSection = 1; openTab("accounts")`。這樣不會疊一層，也不會覆寫記憶。如果想避免改到記憶，也可以在 `openRoute` 加一個 case 來對應。

### Gaps
- 「在子畫面再點同一個分頁會先存再還原、看起來沒反應」是依 Navigation `popUpTo(saveState)+restoreState` 的機制推論出來的，本機沒有 navigation-runtime 2.8.5 的原始碼可以逐行確認，需要實機驗證。
- 沒有逐一列出各分頁所有子畫面的路由，只抽查了代表性的幾個（budget、categorystat、advisor）。
