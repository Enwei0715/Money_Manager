## 1. 還有哪些文字沒套用使用者選的字型？

### Takeaway
App 內畫布文字大致已修好；剩下 1 處 Compose 畫布 TextStyle 從頭建立（地圖版權字）沒帶 fontFamily，以及所有桌面小工具（RemoteViews）與通知一律是系統字型。另有一個隱藏問題：SummaryWidget 甜甜圈是 Bitmap，目前沒寫字，不受影響。

### Cited Findings
- **SpendMapScreen.kt:631（未套字型）**：地圖右下角版權字 `textMeasurer.measure("© OpenStreetMap contributors", TextStyle(fontSize = 9.sp, color = …))`，從零建立 TextStyle、沒有 fontFamily → 永遠系統字型；同一畫面 619 行店名標籤有 `fontFamily = mapFont`（516 行取自 `MaterialTheme.typography.bodySmall.fontFamily`），兩者字型不一致。修法：`MaterialTheme.typography.labelSmall.copy(fontSize = AppText.badge, color = …)`（或 `TextStyle(fontFamily = mapFont, …)`）。 — [SpendMapScreen.kt:631](app/src/main/java/com/enwei/moneymanager/ui/screens/SpendMapScreen.kt)
- **SpendMapScreen.kt:619**：有 fontFamily，但也是 `TextStyle(...)` 從頭建，**漏了 `fontFeatureSettings`（等寬數字 tnum）**；且字級 10.5.sp 不屬於 AppText 字級表。修法：`MaterialTheme.typography.bodySmall.copy(fontSize = AppText.badge 或 label, fontWeight=…, letterSpacing=…)`。 — [SpendMapScreen.kt:619](app/src/main/java/com/enwei/moneymanager/ui/screens/SpendMapScreen.kt)
- **Charts.kt:52/74/98/116（已正確）**：LineChart／DualBarChart 軸標用 `MaterialTheme.typography.bodySmall.copy(fontSize = AppText.badge…)`，有套字型。 — [Charts.kt:74](app/src/main/java/com/enwei/moneymanager/ui/components/Charts.kt)
- **StatsTab.kt:329/371（已正確）**：圓餅標籤 `baseText = MaterialTheme.typography.bodyMedium`。 — [StatsTab.kt:371](app/src/main/java/com/enwei/moneymanager/ui/screens/StatsTab.kt)
- **輸入框**：Form.kt:52、AdvisorScreen.kt:1194、TxnEditor.kt:1037/1105、TxnScreens.kt:136 都是 `MaterialTheme.typography.bodyLarge.merge(TextStyle(color, fontSize = AppText.body))`，merge 保留了 fontFamily → 正確。 — [Form.kt:52](app/src/main/java/com/enwei/moneymanager/ui/components/Form.kt)
- **共用 Text 元件** ui/components/Text.kt 預設 `style = LocalTextStyle.current`，未傳 fontFamily 時沿用主題 → 正確；唯一刻意覆寫是 MoreScreens.kt:365 用 Monospace 顯示 ADB 指令（合理）、AppearanceScreen.kt:130-131 字型預覽（合理）。 — [Text.kt](app/src/main/java/com/enwei/moneymanager/ui/components/Text.kt)
- **桌面小工具全部是系統字型**：res/layout/widget_*.xml 沒有任何 `android:fontFamily`（grep 結果 0 筆），Widgets.kt / SummaryWidget.kt 只用 `setTextViewText`。使用者選「明體／黑體」後，App 內是明體、小工具仍是系統黑體。 — [widget_summary.xml](app/src/main/res/layout/widget_summary.xml)、[Widgets.kt:108-252](app/src/main/java/com/enwei/moneymanager/widget/Widgets.kt)
- **通知**：AppNotices.kt:105-107 用 NotificationCompat 標準樣式，字型由系統決定（無法自訂，屬平台限制，不算 bug）。 — [AppNotices.kt:105](app/src/main/java/com/enwei/moneymanager/notify/AppNotices.kt)
- **SummaryWidget.kt:116** 的 `Paint(Paint.ANTI_ALIAS_FLAG)` 只畫甜甜圈扇形，沒有 drawText → 不受字型影響（若日後在 Bitmap 上寫字需記得設 typeface）。 — [SummaryWidget.kt:112-136](app/src/main/java/com/enwei/moneymanager/widget/SummaryWidget.kt)

### Inferences
- 地圖版權字是 App 內唯一確定「沒跟字型」的畫布文字；修法一行。
- 小工具若要跟字型：RemoteViews 不能 `setTypeface`，可行做法是在 res/font 放 Google Fonts 的 downloadable font XML 並於 layout 用 `android:fontFamily="@font/…"`，但需依使用者設定切換不同 layout（每種字型一份 layout）或把文字畫成 Bitmap。成本高，建議列為「已知限制」而非 P0。

### Gaps
- 未實機驗證：RemoteViews 對 `@font/` downloadable font 在各 Android 版本的支援度（原始碼無法判定）。

## 2. 還有哪些金額繞過 Money（TWD 會出現小數、或缺符號、缺千分位）？

### Takeaway
主要殘留在「股票」模組：`formatNum()`（預設 2 位小數）與 `"%,.0f"`、`"%.2f"` 被直接拿來印「金額」，導致台股現金股利／成交金額出現 `.50`，而美股金額反而被砍成整數。另外 `Money.displayBase` 只在 MainActivity 設定，小工具與背景工作冷啟動時用預設 TWD，非台幣基準的使用者會看到錯誤位數。

### Cited Findings
**A. TWD 金額出現小數（與使用者回報的 bug #2 同型）**
- **InvestScreens.kt:454** 現金股利列：`formatNum(t.cashAmount)`（digits 預設 2）。例：每股 4.5 元 × 333 股 = 1498.5 → 顯示「現金股利  1,498.50」；預期「$ 1,499」（台股）或依持股幣別 `Money.withSymbol(Money.toMinor(t.cashAmount), currency)`。 — [InvestScreens.kt:454](app/src/main/java/com/enwei/moneymanager/ui/screens/InvestScreens.kt)；formatNum 定義 [Components.kt:235-236](app/src/main/java/com/enwei/moneymanager/ui/components/Components.kt)
- **InvestScreens.kt:707** 交易編輯器：`"成交金額 ${formatNum(amount)}　應付 ${formatNum(settle)}"`。零股 3 股 × 123.5 = 370.5 → 「成交金額 370.50　應付 390.50」；預期台股「成交金額 $ 371　應付 $ 391」（金額）。修法：`Money.withSymbol(Money.toMinor(amount), currencyOf(market))`。 — [InvestScreens.kt:707](app/src/main/java/com/enwei/moneymanager/ui/screens/InvestScreens.kt)

**B. 外幣（美股）金額被砍成整數、且無幣別符號**
- **InvestScreens.kt:358/368/405-412/427-438/459**：`formatNum(h.unrealized, 0)`、`formatNum(h.marketValue, 0)`、`formatNum(h.realizedTotal, 0)`、`formatNum(lot.cost - gross, 0)`、`formatNum(t.fee, 0)` 等全用 0 位小數、沒有符號；美股損益 US$12.34 顯示「12」。同一列 365 行市值卻用 `Money.withSymbol(…, h.currency)`（有符號）。預期：一律 `Money.withSymbol(Money.toMinor(v), h.currency)`（台股整數、美股 2 位）。 — [InvestScreens.kt:358-438](app/src/main/java/com/enwei/moneymanager/ui/screens/InvestScreens.kt)
- **StockDetailScreen.kt:275** 預估損益 `"%+,.0f".format(pnl)`（無符號、美股掉小數、0 顯示「+0」）；**:583** `"保本 %,.0f · 市值 %,.0f"`；**:628** `"我已領現金股利 %,.0f 元"`（美股也寫「元」）。預期：`Money.withSymbol` + 依幣別。 — [StockDetailScreen.kt:275/583/628](app/src/main/java/com/enwei/moneymanager/ui/screens/StockDetailScreen.kt)
- **AdvisorScreen.kt:1552** `fun m(v) = Money.withSymbol(v, "TWD")` 寫死 TWD；**:1701/1734** `n(v) = "%,.0f"` 加「元」：「多賺 1,234 元」。 — [AdvisorScreen.kt:1552/1701/1734](app/src/main/java/com/enwei/moneymanager/ui/screens/AdvisorScreen.kt)
- **StockFeeScreen.kt:215** `"成交金額 %,.0f 元 … 原價手續費 ${full.toLong()} 元 · 賣出交易稅 ${tax.toLong()} 元"`：手續費／稅沒有千分位（「1425 元」），單位用「元」與全 App 的「$」不同；**:173** `"已入帳 ${Money.full(...)} 元"`。 — [StockFeeScreen.kt:173/215](app/src/main/java/com/enwei/moneymanager/ui/screens/StockFeeScreen.kt)

**C. 匯率被當成金額取整數（Money 整數化的副作用）**
- **MoreScreens.kt:257** 工具格副標：`"1 USD ≈ ${Money.format(lk.fx.convert(100, "USD"), "TWD")} TWD"`。FxConverter.convert 轉成 TWD 時四捨五入到「元」（Money.kt:93），所以 1 USD = 32.4 TWD 顯示「1 USD ≈ $32 TWD」，匯率精度消失，且「$」與「TWD」重複。預期「1 USD ≈ 32.40 TWD」（匯率保留 2～4 位，如同 :823-825 的 `%.4f`）。 — [MoreScreens.kt:257](app/src/main/java/com/enwei/moneymanager/ui/screens/MoreScreens.kt)、[Money.kt:88-94](core/src/main/kotlin/com/enwei/moneymanager/core/Money.kt)

### Inferences
- 根因是兩個平行的格式化系統：core 的 `Money.*`（以 minor Long、依幣別）與 UI 的 `formatNum/formatPct`（Double、不知幣別）。股票模組持有的是 Double 金額，因此大量繞過 Money。建議在 core 加 `Money.of(v: Double, currency)`（= withSymbol(toMinor(v), currency)）、`Money.price(v)`、`Money.pct(v, signed)`，然後把 `formatNum(x, 0)`／`"%,.0f"` 用於金額的地方全部換掉。

### Gaps
- 未確認 `h.currency` 對台股一定是 "TWD"（若是空字串，`decimalsOf("")` 會走 2 位小數）；需看 Holding 建構處。

## 3. 單位、符號、百分比、負號、張/股是否一致？

### Takeaway
同一個概念在不同頁至少有 2～3 種寫法：「$ 1,234」/「$1,234」/「1,234 元」；負數「$ -1,234」/「-$1,234」/「-$ 1,234」；百分比「54.8 %」/「54.8%」/「55%」/「+1.23%」/「+1.2%」；括號全形/半形混用；股數有時沒千分位。

### Cited Findings
**符號與空格**
- `Money.withSymbol` →「$ 1,234」（有空格）；`Money.format(v, cur)` →「$1,234」（無空格）。後者仍用在：StatsTab.kt:446/468（趨勢大字與「平均 $12,345」）、Components.kt:96 `AmountText`（RecurringScreens.kt:92/96/117、TxnScreens.kt:355）。同 App 其他列表、小工具、通知都是「$ 1,234」。修法：AmountText 改 `Money.withSymbol`。 — [Components.kt:96](app/src/main/java/com/enwei/moneymanager/ui/components/Components.kt)、[StatsTab.kt:446/468](app/src/main/java/com/enwei/moneymanager/ui/screens/StatsTab.kt)
- 「元」作單位：StockFeeScreen.kt:173/215、StockDetailScreen.kt:599/621/622/628、AdvisorScreen.kt:1734、NumberField suffix「元」(AdvisorScreen.kt:1782/1787/1788/1928、StockFeeScreen.kt:83/84)、AdvisorTools.kt:171（AI 工具文字「共 1,234 元」）。其中「每股股利 x 元」「手續費下限 20 元」這類單價/設定值用「元」可以接受；但「已入帳 1,234 元」「我已領現金股利 1,234 元」是金額，應與全 App 一致用「$ 1,234」。未發現「NT$」字串。 — [StockFeeScreen.kt:173](app/src/main/java/com/enwei/moneymanager/ui/screens/StockFeeScreen.kt)
- 同一行混用有符號與無符號：Widgets.kt:139「本月支出 $ 12,000 · 結餘 3,000」、SummaryWidget.kt:91「收入 $ 50,000　結餘 12,000」、AccountsTab.kt:620「未出帳 $ 3,000　可用額度 47,000」。預期同一行全帶或全不帶符號。 — [Widgets.kt:139](app/src/main/java/com/enwei/moneymanager/widget/Widgets.kt)、[SummaryWidget.kt:91](app/src/main/java/com/enwei/moneymanager/widget/SummaryWidget.kt)、[AccountsTab.kt:620](app/src/main/java/com/enwei/moneymanager/ui/screens/AccountsTab.kt)

**負號**
- `withSymbol(-1234)` →「$ -1,234」（Money.kt:65-67）；`format(-1234,"TWD")` →「-$1,234」（Money.kt:43-46）；交易列 `"-" + withSymbol(...)` →「-$ 1,234」（Widgets.kt:241-242）；小工具預覽 widget_accounts_preview.xml:27 寫「-$ 12,480」，但實際帳戶小工具 Widgets.kt:205 對負餘額（信用卡）輸出「$ -12,480」→ 預覽與實際不同。建議 Money 統一為「-$ 1,234」（負號在符號前），修 withSymbol 一處即可全 App 生效。 — [Money.kt:43-67](core/src/main/kotlin/com/enwei/moneymanager/core/Money.kt)、[Widgets.kt:205/242](app/src/main/java/com/enwei/moneymanager/widget/Widgets.kt)、[widget_accounts_preview.xml:27](app/src/main/res/layout/widget_accounts_preview.xml)
- 正號：InvestScreens.kt:230、AccountsTab.kt:383、Widgets.kt:175 手動加「+」；InvestScreens.kt:368/406/407 `LabelValue("預估損益", formatNum(...))` 不加「+」，但旁邊百分比 `formatPct` 有「+」→「損益 1,234 (+1.23%)」。 — [InvestScreens.kt:368](app/src/main/java/com/enwei/moneymanager/ui/screens/InvestScreens.kt)

## 4. 固定字級（sp 字面值）與大字體溢出風險

### Takeaway
sp 字面值已大幅收斂到 AppText；殘留的多是 lineHeight 與地圖文字。較大的風險是小工具 XML 的主金額沒有 maxLines，以及 `LabelValue`/`AmountText` 等元件沒有單行限制，大字體時數字會斷行。

### Cited Findings
- 字面值 sp：SpendMapScreen.kt:619（10.5.sp、letterSpacing 0.2.sp）、:631（9.sp）不在 AppText 字級表；StatsTab.kt:373 圓餅 `lineHeight = 16.sp` 搭 AppText.secondary 13.5sp（比例 1.19，CJK 兩行偏擠）；MoreScreens.kt:219 body 14sp 配 lineHeight 17.sp 且 maxLines=2；TransactionsTab.kt:924 badge 10sp 配 lineHeight 10.sp（1.0 倍，CJK 上下會被裁）；UpdatePrompt.kt:107 17.sp、TransactionsTab.kt:1086 24.sp、MainActivity.kt:517 12.sp。修法：lineHeight 改用 `em`（如 1.3.em）或直接用 typography 樣式。 — [TransactionsTab.kt:924](app/src/main/java/com/enwei/moneymanager/ui/screens/TransactionsTab.kt)、[StatsTab.kt:373](app/src/main/java/com/enwei/moneymanager/ui/screens/StatsTab.kt)、[MoreScreens.kt:219](app/src/main/java/com/enwei/moneymanager/ui/screens/MoreScreens.kt)
