# 帳理對話可刪可復原，裁切剩三類

**AI 對話管理已經做完，不必改儲存格式**：新增對話、清除所有訊息、刪除這段對話、刪除單組問答、刪除一段過去對話、全部刪除，都已在 commit 08cf97f 完成，而且每一種都能復原。紅色角標被切、浮動按鈕（FAB）蓋住金額、推估圖標籤出界也已在 75d7694 一起修好。剩下的裁切問題都同一個原因：**高度、寬度和換版判斷用固定 dp，字卻跟著系統字級放大**。App 的字級倍率是「系統字級（限 0.85～2 倍）× App 字體大小」，所以 200% 時一行 14sp 的字要佔 40dp 高。目前剩三類問題：固定高度的格子裁掉文字；金額放在平分寬度的欄位裡，被「…」吃掉位數；Canvas 文字畫出畫布外，其中有兩處可能閃退。要一次防住，做法是在共用元件裡定規則，不是逐頁修：Text wrapper 自動配行高（工作區已在做），容器改用 `heightIn(min=)`，金額欄不加 weight 並改用 FitText，Canvas 文字一律用 `maxOf(0f, …)` 夾在畫布內。以下行號都相對於 `app/src/main/java/com/enwei/moneymanager/`。

## 對話管理六個動作已完成，刪除都能復原

原本的資料模型就支援多段對話。「目前對話」存在 `news/chat.json`，「過去對話」存在 `news/chats.json`，最多 30 段，由新到舊排列（[NewsDataset.kt:153-180](app/src/main/java/com/enwei/moneymanager/data/NewsDataset.kt)）。舊的單一大檔會自動轉成這個格式。備份會匯出 `chat` 與 `chatThreads`，還原時如果備份裡沒有過去對話，就保留手機上現有的（[FullBackup.kt:112, 180-184](app/src/main/java/com/enwei/moneymanager/data/FullBackup.kt)）。所以這次**資料遷移、備份格式都不用動**。刪除後 AI 也不會再讀到被刪的內容，因為每次提問都重新讀取 store，取目前對話的 `takeLast(6)` 當上下文（[Advisor.kt:642-656, 718-719](app/src/main/java/com/enwei/moneymanager/data/Advisor.kt)）。

| 功能 | 狀態 | 行為 |
|---|---|---|
| 新對話 | 已完成（原有） | 目前對話收進「過去的對話」，回覆進行中不能按 |
| 清除所有訊息／刪除這段對話 | 已完成（08cf97f） | 先跳確認，刪完可復原。「刪除」會自動接回最近一段過去對話；「清除」會留下一段空白對話 |
| 刪除單組問答 | 已完成（08cf97f） | 問題和回答一起刪，可復原。AI 正在回答最後一個問題時，這組不能刪 |
| 刪除一段過去對話 | 已完成（08cf97f） | 不跳確認，刪完可復原 |
| 全部刪除過去對話 | 已完成（08cf97f） | 先跳確認，刪完可復原，目前對話不受影響 |
| 「刪除資料庫」按鈕 | 已完成（08cf97f） | 只有過去對話、沒有目前對話時，原本按不下去；現在按得下去 |

「回覆進行中不能刪最後一個問題」是必要的限制。AI 的回覆會寫回「當下的目前對話」（[Advisor.kt:803](app/src/main/java/com/enwei/moneymanager/data/Advisor.kt)），問題如果先被刪掉，回答就會變成沒有問題的孤兒回答。還有三件事沒做，都不是必要：**每日選股會從所有對話裡找「請檢討近…」的結論**（[Advisor.kt:583-586](app/src/main/java/com/enwei/moneymanager/data/Advisor.kt)），刪掉這類對話時，確認文字最好提醒「之後選股不再參考這次檢討」；長按選單只綁在文字泡泡上，圖表和股票卡長按沒有反應；目前對話超過 40 則、過去對話超過 30 段時，最舊的會被直接丟掉，畫面上沒有任何提示。

## 角標與浮動按鈕已改成共用元件

使用者回報「新聞紅色數字右上方被擋住」，原因是 4 顆計數角標都寫成 `IconButton { BadgedBox { Icon } }`。BadgedBox 會把角標往圖示右上角外推，M3 IconButton 又把內容裁成 40dp 的圓。右上角正好是圓形切掉最多的地方。投資頁的角標沒有包 `ChromeScale`，字級沒有上限，兩位數或大字級時被切得更多。受影響的是新聞篩選數（[AdvisorScreen.kt:1177](app/src/main/java/com/enwei/moneymanager/ui/screens/AdvisorScreen.kt)）、報告歷史數、過去對話數，以及交易頁的待確認數。**75d7694 新增了 `BadgedIconButton`／`CountBadge`**（[CountBadge.kt](app/src/main/java/com/enwei/moneymanager/ui/components/CountBadge.kt)），換掉全部 5 處 BadgedBox。角標改畫在 48dp 觸控區的內側，包 ChromeScale，超過 99 顯示「99+」。

同一個 commit 也把交易、週期、投資三頁的 FAB 改成 **`ScrollAwareFab`，往下捲時收起**。截圖裡原本被蓋住的「−$ 120.00」和日合計就是這個問題。推估圖的標籤原本只夾住 x 座標，價位線靠近上下緣時會被 `clipToBounds` 切掉一半，現在 y 座標也夾住了（[StockDetailScreen.kt:1295](app/src/main/java/com/enwei/moneymanager/ui/screens/StockDetailScreen.kt)）。這三項都標為**已完成**。

## 金額被「…」吃掉，比被遮住更危險

位數被吃掉的金額會被當成另一個數字讀，比整個看不到更容易誤導。交易列本身寫得對：說明文字欄加 `weight(1f)`、金額欄不加 weight，金額會先量。下面這些地方沒照這個寫法。**SummaryBar／SummaryBarCustom** 判斷要不要換版時只看 dp 寬（[TransactionsTab.kt:446-476](app/src/main/java/com/enwei/moneymanager/ui/screens/TransactionsTab.kt)、[AccountsTab.kt:468-492](app/src/main/java/com/enwei/moneymanager/ui/screens/AccountsTab.kt)），三欄平分，200% 時合計被省略。**DayBlock 日標題**的收入、支出各佔一半寬，收入是空的也佔位（[TransactionsTab.kt:617-634](app/src/main/java/com/enwei/moneymanager/ui/screens/TransactionsTab.kt)）。**FilterRow** 的名稱沒加 weight，長的分類名稱會把右邊的金額擠到 0 寬（[FilterScreen.kt:286-303](app/src/main/java/com/enwei/moneymanager/ui/screens/FilterScreen.kt)）。**折線／長條圖底下的數字**在 12 期時每欄約 26dp，正常字級下就會變成「12,3…」（[Charts.kt:84-91](app/src/main/java/com/enwei/moneymanager/ui/components/Charts.kt)）。**FitAmount** 的最小字級用 sp 定，最小值也跟著字級放大，200% 時日曆格裡的金額最後還是被省略（[TransactionsTab.kt:1013-1021](app/src/main/java/com/enwei/moneymanager/ui/screens/TransactionsTab.kt)）。另外有兩個中等問題：LabelValue 共用了 18 處，值會被省略；分帳金額欄固定 88dp，輸入的算式會被「…」蓋掉（[TxnEditor.kt:1450](app/src/main/java/com/enwei/moneymanager/ui/screens/TxnEditor.kt)）。

Canvas 有**兩處 `coerceIn(0f, size.width - w)`，標籤比畫布寬時夾住的範圍會變空，直接閃退**。一處是圓餅標籤（[StatsTab.kt:448](app/src/main/java/com/enwei/moneymanager/ui/screens/StatsTab.kt)），長的自訂分類名稱在 200% 時就會觸發。另一處是 K 線的買賣理由（[StockDetailScreen.kt:922](app/src/main/java/com/enwei/moneymanager/ui/screens/StockDetailScreen.kt)）。其他 Canvas 問題只影響外觀，不會閃退：圓餅中間的總額比圓環中間的洞寬（[StatsTab.kt:364-369](app/src/main/java/com/enwei/moneymanager/ui/screens/StatsTab.kt)）；Y 軸寬度固定 44dp，標籤會畫到左邊界外（[Charts.kt:47-75](app/src/main/java/com/enwei/moneymanager/ui/components/Charts.kt)）；K 線價位標籤往下疊沒有上限，會蓋到成交量區（[StockDetailScreen.kt:801-861](app/src/main/java/com/enwei/moneymanager/ui/screens/StockDetailScreen.kt)）。

## 寫成元件規則，一次防住整類

最省力的修法是改共用元件，各頁自然套用。**進行中**：工作區的 [Text.kt](app/src/main/java/com/enwei/moneymanager/ui/components/Text.kt) 加了 `fitLineHeight`，只指定字級時行高自動用 1.3 倍，指定的行高小於 1.2 倍時拉到 1.2 倍。原本沒指定行高的字一律用主題的 20sp 行高，26sp 的大標題因此上下被切、換行時兩行重疊，10sp 的小字則佔了兩倍高度。這個改動會一起解決這兩個問題，也會減輕統計趨勢圖被擠的程度。其餘規則還沒做，都列入待辦，每條都對應上面的項目。第一，含文字的容器不寫死高度，`height` 一律改 `heightIn(min=)`。第二，平分畫面的版面判斷要用內容高度（`sp.toDp()`）；平分模式下不用 `clipToBounds`。第三，金額欄不加 weight；並排的摘要金額一律用 FitText，最小字級用 dp 換算，真的放不下就改用萬或 k 縮寫，**絕不出現「12,3…」**。第四，項目可能超過螢幕寬的 Row 要能左右捲動。第五，加一個共用的 `clampX/clampY`，上限用 `maxOf(0f, …)`，TextMeasurer 一律給 `maxWidth`。第六，禁止直接用 `material3.Text` 繞過 wrapper，目前有 [AdvisorScreen.kt:1875](app/src/main/java/com/enwei/moneymanager/ui/screens/AdvisorScreen.kt) 和 [MoreScreens.kt:367](app/src/main/java/com/enwei/moneymanager/ui/screens/MoreScreens.kt) 兩處，可以用 grep 檢查。

驗收方式：在截圖流程加一輪「`font_scale 2.0`＋英文介面＋320dp 寬」，拍日曆、年曆、工具、統計、資產、記帳，再加「新聞篩選啟用」和「報告歷史 12 份」兩張角標截圖。目前月曆、工具格、統計圖的裁切都是從程式碼推算的，只有截圖能確認門檻，修好後也能防止再犯。

## Conclusion

這次的問題看起來分散，其實只有一個共同原因：**版面用 dp 推算，內容用 sp 長大**。角標和 FAB 已經改成共用元件，從此不會再出現同樣的問題。文字裁切也應該照這個做法，寫進 Text wrapper、FitText 和 Canvas helper，不要逐頁修。否則下一個新頁面寫一個 `height(40.dp)`，問題又會回來。

對話管理剩下的風險不在「刪不掉」，而在「刪了會影響什麼」。過去對話裡的檢討結論會影響每日選股，刪除這類對話時要告訴使用者。目前對話和過去對話在超過上限時會被直接丟掉，也要讓使用者知道。這兩點都只需要改提示文字，不用改資料模型。
